## arc_to_zen 0.2.1

Fixes migration stopping with “Browser-folder symlinks are not supported; no live files were changed” on normal Arc folders.

### Fix

- Exclude Arc/Chromium runtime markers (`SingletonSocket`, `SingletonCookie`, `SingletonLock`, and `RunningChromeVersion`) from backups and file manifests. These markers can be dangling symlinks after Arc exits.
- Keep unexpected browser-folder symlinks blocked and preserve verified backup and recovery checks.
- Add regression coverage for runtime symlinks in backups, migration, and restoration.

### Downloads

Choose `arm64` for Apple Silicon (M1 and later) or `x64` for Intel. Both require macOS 14 or later.

- **ZIP:** Extract and move `arc_to_zen.app` to Applications.
- **DMG:** Open the disk image and drag the app to Applications.
- **SHA-256:** Download both files for your architecture, then run `shasum -a 256 -c arc_to_zen-0.2.1-macos-ARCH.sha256` from the download folder.

### Validation and compatibility

The release workflow runs regression tests, lint, formatting, and source privacy checks on both macOS architectures, then builds and verifies ad-hoc code signatures.

Builds are **ad-hoc signed, not Apple-notarized**. Read the [compatibility guide](https://github.com/MohamedRF/arc_to_zen/blob/v0.2.1/docs/compatibility.md) before migrating important data.

Quit Arc and Zen completely before migration. Full verified backups remain mandatory; a separate Zen profile is the default.
